# Проверка в Zabbix и vCenter

Предыдущая редакция была импортирована и повторно импортирована через Zabbix 8.0.0 и проверялась read-only на vCenter 8.0.3 с vSAN OSA. Проверены inventory, cached health, capacity, host/disk performance, VM performance discovery и сбор доступных VM показателей. ESA, stretched cluster, ненулевые причины resync и поведение при отключённом Performance Service на живой системе не подтверждены.

Текущая опубликованная редакция добавляет ежедневный сбор статических характеристик дисков и меняет интервалы опроса. Её YAML собран из исходника, но повторный импорт этой редакции в живой Zabbix не выполнялся. Перед production deployment проверьте YAML импортом в тестовом окружении и сравните Latest data с vCenter.

На vCenter 8.0 U3 `VsanPerfGetSupportedEntityTypes` требовал `System.Read` на корневом inventory; при отсутствии permission performance capability discovery недоступен. Время performance `YYYY-MM-DD HH:mm:ss` обрабатывается как UTC; другие timezone отдельно не проверялись.

Масштаб latency приблизительно соотнесён с графиками одной версии 8.0 U3: сырые значения трактуются как микросекунды даже при `time_ms` в метаданных. Точная сверка одного timestamp/window не подтверждена. Поэтому триггеры latency отключены по умолчанию; перед включением сравните один и тот же период в своей системе. Старые данные предыдущих импортов автоматически не удаляются.

Шаблон использовал только read-only API и не менял конфигурацию VMware, не включал Performance Service и не требовал изменений конфигурационных файлов Zabbix. Синтетические fixtures покрывают отдельные ошибки и форматы API; их успешная обработка не подтверждает поведение для всех версий vSAN.
