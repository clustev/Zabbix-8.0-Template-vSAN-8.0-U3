# Архитектура

Один Zabbix host представляет vCenter. 12 независимых Script master items (`inventory`, `topology`, `health`, `capacity`, `objects`, `resync`, `disks`, `diskmeta`, `smart`, `performance`, `witness`, `pools`) создают read-only сессию, получают inventory и выполняют категорийные запросы. Затем работают dependent items, LLD, prototypes и triggers. Между выполнениями состояние JavaScript не сохраняется; masters повторно получают inventory. Несколько категорий отдельно читают cached Skyline. Для ESA pools запрос выполняется по подключённым хостам.

Возможности API определяются по версии и опубликованным performance entity/counters; фактически отсутствующие поля/сервисы проверяются в ответах. Это best-effort capability discovery, а не полный предварительный каталог методов vCenter. Неполные ответы не превращаются в нули и не удаляют результаты discovery.

`health` использует только кэш Skyline. `diskmeta` раз в день извлекает статические поля дисков из того же кэшированного summary; принудительная проверка здоровья не запускается. Отсутствующий или устаревший кэш даёт диагностическую ошибку. `performance` опрашивает только счётчики, опубликованные уже включённым Performance Service, для cluster/host/disk/virtual-machine. Если service выключен, категория выдаёт причину недоступности, остальные категории продолжаются.

Ключи основаны на MoID кластера/хоста/datastore/VM и UUID диска/group/witness либо ID API checks; имена предназначены для отображения и фильтрации. SMART сопоставляется по host/disk name. ESA pool без UUID использует MoID host только при единственном pool; при неоднозначности discovery сохраняет прежние результаты. Успешное пустое discovery отключает объекты через 7d и удаляет через 30d; ошибки и частичные ответы не выдают пустой список.

Latency переводится в секунды по наблюдаемому расхождению на vSAN 8.0 U3: графическое `time_ms` сопоставлялось с сырыми микросекундами. Это оценка по одной среде, а не подтверждённый контракт; проверяйте на своей версии. IOPS/throughput totals складываются только для совпадающих timestamps. Capacity bytes сохраняются десятичными строками для точных вычислений.

Resync reasons берутся из `QuerySyncingVsanObjectsSummary` в ограниченной выборке до 100 объектов; это не полный список причин. Скорость чтения resync — `cluster-domcompmgr.tputResyncRead`, не суммарная скорость передачи/копирования. Host и OSA disk performance запрашиваются пачками до 50 querySpecs; VM performance discovery ищет VM, у которых в inventory есть vSAN datastore.

Код закрывает временные views и SOAP session в `finally`, кроме принудительного timeout. Пароли и cookies не возвращаются в JSON. Размер ответа и количество объектов ограничены, но длительное последовательное чтение больших inventory может превысить timeout.

Для явно возвращённого API состояния `inaccessible` есть отдельный LLD/trigger. Если состояние перестало возвращаться, новое значение не подставляется; событие закроется по nodata и не подтверждает восстановление. Ошибки/свежесть object health контролируются отдельно.
