# Права

Используйте отдельную сервисную учётную запись с правами чтения только на объекты, которые надо мониторить. Для inventory/API вызовов нужен `System.View` и/или `System.Read` на соответствующих папках/объектах; на практике часто требуется `System.Read` на корневой inventory-папке для `CreateContainerView` и чтения performance capabilities, а также видимость целевых кластеров, хостов и datastore. Не назначайте write/admin права.

Проверяйте фактические права для установленных версий и локальной модели ролей: VMware API методы проверяют привилегии на разных Managed Objects. В частности, документация требует `System.Read` для [Skyline Health и SMART](https://dp-downloads.broadcom.com/api-content/apis/API_VMA_001/8.0U3/html/vim.cluster.VsanVcClusterHealthSystem.html), на host для [QueryVsanManagedDisks](https://dp-downloads.broadcom.com/api-content/apis/API_VMA_001/8.0U3/html/vim.cluster.VsanVcDiskManagementSystem.html), и соответствующие права для [Performance Manager](https://developer.broadcom.com/xapis/vsan-management-api/latest/vim.cluster.VsanPerformanceManager.html), [Space](https://developer.broadcom.com/xapis/vsan-management-api/latest/vim.cluster.VsanSpaceReportSystem.html), [Object System](https://developer.broadcom.com/xapis/vsan-management-api/latest/vim.cluster.VsanObjectSystem.html), [Stretched Cluster](https://developer.broadcom.com/xapis/vsan-management-api/latest/vim.cluster.VsanVcStretchedClusterSystem.html) и [ViewManager](https://developer.broadcom.com/xapis/vsphere-web-services-api/latest/vim.view.ViewManager.html).

Это read-only baseline, а не универсальный гарантированный список минимальных привилегий для всех версий и локальных политик. Шаблон не требует прав изменения VMware. Ошибка доступа отображается в диагностических items; выдавайте дополнительные права только на чтение после проверки конкретного API метода.
